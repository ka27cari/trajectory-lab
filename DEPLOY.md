# Deploy Trajectory Lab with GitHub and Posit Connect Cloud

**GitHub stores the source. Posit Connect Cloud hosts the running Shiny app.** This project intentionally does not include hand-written or fabricated `manifest.json` or `renv.lock` files.

## 1. Test locally

Install R and open RStudio, Positron, or an R console in the repository root.

```r
source("install.R")
shiny::runApp(".")
```

Open all tabs, generate two datasets with the same seed, check downloads, and upload a small CSV. Then run:

```sh
Rscript tests/run_tests.R
```

The GitHub Actions workflow tests pure functions and parses app sources on every push, but **does not replace an interactive browser smoke test**.

## 2. Record dependencies in your real R environment

Posit Connect Cloud's official R/Shiny GitHub deployment guide requires a `manifest.json` generated by `rsconnect` from the project directory. Do not invent a manifest by hand.

```r
install.packages("rsconnect", repos = "https://cloud.r-project.org")
rsconnect::writeManifest()
```

Check that `manifest.json` exists before committing. To snapshot exact versions for future local development, optionally initialize and snapshot `renv` **after confirming the app runs in your own environment**:

```r
install.packages("renv", repos = "https://cloud.r-project.org")
renv::init(bare = TRUE)
renv::snapshot()
```

If you enable `renv`, review its generated files and commit `renv.lock` and appropriate project activation files. Do not commit `renv/library`, credentials, real user uploads, or `.Rhistory`.

## 3. Publish the code through GitHub Desktop

- In GitHub Desktop, choose **File → Add local repository**, select the extracted folder, and choose **Create a repository here** if prompted.
- Give the repository a name such as `trajectory-lab`.
- Commit project files including `.github/workflows/r-tests.yml`, `README.md`, and the generated manifest.
- Click **Publish repository** and select Public if you want it showcased publicly.
- Confirm the workflow succeeds on GitHub under the **Actions** tab.

## 4. Connect the app to hosting

1. Sign in to [Posit Connect Cloud](https://connect.posit.cloud/).
2. Connect your GitHub account and select the public repository.
3. Follow the Shiny for R GitHub publishing flow and choose the repository containing `app.R` and `manifest.json`.
4. Deploy the application, check runtime logs, and test generation/upload/export in its public URL.
5. Put the verified live URL near the top of `README.md` under a `Live demo` link.

The host may build its own dependencies based on your manifest. Deployment errors cannot be diagnosed until the project is run in the target environment. The app does not use external APIs, databases, or environment secrets.

Official references:
- https://docs.posit.co/connect-cloud/how-to/r/shiny-r.html
- https://shiny.posit.co/r/getstarted/

## GitHub Pages alternative?

GitHub Pages does **not** execute ordinary server-based R/Shiny applications. Shinylive/WebAssembly is a different packaging and runtime model requiring a compatibility assessment; this repository is not a Shinylive package.
